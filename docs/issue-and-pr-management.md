# Contributing issues and pull requests

For [nomad-simulations](https://github.com/FAIRmat-NFDI/nomad-simulations),
[simulation-parsers](https://github.com/FAIRmat-NFDI/nomad-parser-plugins-simulation),
[nomad-results-normalizer](https://github.com/FAIRmat-NFDI/nomad-results-normalizer), and
[nomad-simulation-apps](https://github.com/FAIRmat-NFDI/nomad-app-plugins-simulation).

## Issues

1. Search existing issues and PRs first. Add context to an existing issue when it covers the same problem.
2. Otherwise, use the issue template when available and file the issue where the code or documentation needs to change.
3. State the problem, expected result, and a useful example. Link dependencies and related tasks across repositories.

## Pull requests

Use the repository's PR template when available and complete the applicable sections.

- Link issues and explain the change, purpose, and dependencies.
- Describe validation; for scientific changes, check values, units, shapes, and provenance as applicable. Follow repository-specific test instructions.
- Use Draft until ready, then request review and identify open design questions.
- Use closing references only for fully resolved issues. Update linked issues with outcomes and remaining gaps.

## Tracking work

Maintainers triage issues and PRs using these properties:

| Property | Purpose |
|---|---|
| Priority (issues only) | Order of execution. |
| Labels | Work type and affected areas or components. |
| Milestone, when applicable | Release or delivery goal. |
| Project and status | Workflow state. |
| Assignee / reviewers | Responsibility for work and review. |

Keep progress, blockers, and next actions current. Deferred work that has not
started stays in Backlog; On hold means previously started work has paused.
See the [maintainer guide](maintainer-guide.md) for property definitions and triage procedures.
